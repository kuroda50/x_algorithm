# X レコメンド・ビートオーケストラ

X（旧 Twitter）のおすすめフィードのアルゴリズムを、楽器の並んだ 3D ステージで可視化するブラウザ用シミュレーション。Animusic の「Pipe Dream」に着想を得ていて、投稿がボールになって楽器に当たって跳ねていき、当たった瞬間の音がそのまま曲になります。エージェント（仮想ユーザー）の反応が、人ごとのフィードの偏り（フィルターバブル）を作っていく様子を眺められます。

## 起動

```bash
npm install
npm run dev
```

テスト・型チェック・ビルド:

```bash
npm test
npm run typecheck
npm run build
```

## 画面の見方

- **3D ステージ（画面全体）**: 投稿（話題ごとの色のボール）が、フォロー内・フォロー外の 2 本のパイプから発射され、ドラム・ビブラフォン・ベース・ベルの楽器を順に鳴らしながらエージェントへ届きます。はじかれた投稿はスクラップ箱へ、選抜で漏れたものは落選箱へ落ちます。ドラッグで視点を回せます。エージェントをクリックするとフィードが見られます。
- **フィード（左下）**: エージェントを選ぶと、その人の興味ベクトルとフィード上位 6 件が表示されます。未選択時は全エージェントのフィード構成の一覧が出ます。
- **フィードの偏り（右下）**: 偏り指数とエージェント間の類似度の時系列。偏り指数が上がり、類似度が下がるほど、人ごとにフィードが分かれています。
- **設定（右上の「設定」ボタン）**: スコアリングの重み・多様性ペナルティ・フォロー外の係数・興味の更新速度などを変えられます。

## 楽器と工程の対応

音はすべて、ボールが楽器やエージェントに当たった瞬間に鳴ります。

| 工程（実際の構成） | 楽器 | 起きること |
|---|---|---|
| 候補取得（Thunder / Phoenix 検索） | 2 本のパイプ | フォロー内・フォロー外の投稿が 16 分音符ごとに 1 個ずつ発射される |
| フィルタ | ドラム | 通過した投稿がキック・スネア・ハットを鳴らす。スパムや古い投稿はシンバルに弾かれてスクラップ箱へ |
| スコアリング | ビブラフォン | スコアが高い投稿ほど高い音の鍵盤に落ち、大きくなる |
| 多様性調整 | ベース | 同じ投稿者の 2 件目以降とフォロー外の投稿は、弦に当たると小さくなる |
| 選抜 | ベル | 上位 3 件だけがベルを鳴らしてエージェントへ飛ぶ。残りは落選箱へ |
| フィード | エージェントの受け皿 | 話題ごとの高さの音で届く。反応するとキラッと鳴り、その話題の地区へ寄っていく |

## 音の仕組み

1 拍につきエージェント 1 体がフィードを要求し、フォロー内 4 件・フォロー外 4 件が 16 分音符ごとに発射されます。各ボールは 1 拍ごとに次の楽器に当たります。音程はコード進行（C → Am → F → G、4 拍ごと）と C のペンタトニックに揃えてあります。音はすべて Web Audio API で合成していて、音声ファイルは使っていません。

## 工程と X のアルゴリズムの対応

公開されている構成（xai-org/x-algorithm と、2023 年公開の twitter/the-algorithm）に対応しています。

| 工程 | 実際の構成 | このシミュレーションでの処理 |
|---|---|---|
| 0: フォロー内 | Thunder: フォロー中アカウントの最近の投稿 | フォローしている投稿者の未読の新しい投稿の中から、興味に近いもの |
| 0: フォロー外 | Phoenix Retrieval: 埋め込み類似度で取得 | フォローしていない投稿者の未読投稿を、興味との近さ順に |
| 1: フィルタ | Pre-scoring filters | スパムと古すぎる投稿を除外 |
| 2: スコアリング | Phoenix Scorer + Weighted Scorer | `score = wLike·P(いいね) + wReply·P(リプライ) + wRepost·P(リポスト)` |
| 3: 多様性調整 | Author Diversity Scorer / OON Scorer | 同じ投稿者の 2 件目以降を減衰、フォロー外に係数を掛ける |
| 4: 選抜 | Selection | スコア上位 K 件だけがフィードへ進む |
| 5: エージェント | フィード表示。行動が次回の入力になる | 反応すると興味ベクトルが更新される |

## 簡略化している点

- 予測モデル（いいね・リプライ・リポストの確率）の代わりに、話題ごとの興味ベクトルと投稿の品質から決めています。数値は実際の値ではありません。
- 反応はいいね・リプライ・リポストの 3 種類だけです。
- 反応すると、その話題の興味が今の興味に比例して増えます（反応がなければ少し減ります）。フォロー外の投稿にリプライ・リポストすると、一定の確率でその投稿者をフォローします。
- フィードの要求は 1 拍に 1 体ずつ順番に行われます。実際は全ユーザーがそれぞれのタイミングでフィードを要求します。
- 候補は 1 回の要求につきフォロー内 4 件・フォロー外 4 件だけです。実際は桁違いに多く取ってから絞り込みます。
- 最初は全員が、どの話題からも同じ人数をフォローし、興味もほぼ均等です。差は反応の積み重ねだけから生まれます。
- 投稿者・話題・エージェントはすべてシード付き乱数で生成する仮想のもので、実データは使いません。
